# Отчёт: блок 2 — Uralia Update System + бой в реальном времени + VIP-ускорение

## Что сделано
**Система обновлений (контент без нового APK)**
- Формат пакета — ZIP только с данными: `.glb .png .jpg .webp .ogg .json .txt`. Проверка выполняется при публикации и повторно на клиенте: запрещены скрипты, сцены, нативные библиотеки и resource packs, небезопасные пути; проверяются JSON и сигнатура glTF. Клиент загружает данные рантайм-импортёрами Godot (GLTFDocument, Image, AudioStreamOggVorbis), из пакета ничего не исполняется.
- Сервер:
  - хранилище файлов по SHA-256 (можно зеркалировать на CDN 1:1);
  - таблица `content_package_versions` (миграция 0002);
  - каждая операция выпускает новый неизменяемый подписанный манифест;
  - CLI `python -m app.content.admin`: build, publish, list, activate (откат), remove, kill on/off, promote между каналами, min-client, keygen, set-vip;
  - `/content/files/{sha256}` отдаёт файлы с HTTP Range (206) и immutable-кешем;
  - зависимости проверяются и упорядочиваются; у каждого пакета своя минимальная версия клиента, старые клиенты такой пакет пропускают, а не обязаны обновлять APK.
- Клиент (автозагрузка `Content`):
  - проверка RSA-подписи манифеста;
  - загрузка кусками по 512 КБ с докачкой после обрыва, даже после перезапуска приложения;
  - проверка свободного места и SHA-256;
  - атомарное переключение набора пакетов, предыдущий набор хранится для отката;
  - kill switch возвращает встроенный контент;
  - отчёты об установке на сервер;
  - периодическая проверка манифеста раз в 15 минут.
- Обязательные пакеты загружаются до входа в игру (экран загрузки с прогрессом). Необязательные — в фоне во время игры и применяются в безопасный момент (экран крепости) без перезапуска.
- Через пакеты обновляются: облики героев (`looks/<code>.json`, в том числе на новых `.glb`-ригах), декор крепости (`fortress/decor.json`), музыка (`music/<id>.ogg`). Демо-пакет «Осенняя ярмарка» лежит в `content_src/fortress_autumn_fair`.

**Бой**
- Серверная детерминированная симуляция в реальном времени: все юниты обеих сторон действуют одновременно. Лог событий с метками времени: перемещения, начало атаки, момент попадания.
- Клиент — вид сбоку в стиле AFK: отряд слева, враги справа, модели развёрнуты на три четверти к камере. Внизу карточки героев со здоровьем и энергией, таймер 90 с. Снаряды, ударные волны и смерти воспроизводятся параллельно.
- Скорость x1/x2 доступна всем, x4 — с VIP 1, x6 — с VIP 3. Сервер передаёт разрешённые скорости в профиле, в настройках видно, что откроет следующий уровень VIP.

## Проверки (реально запущены)
- pytest: SQLite — 20 passed, 2 skipped; PostgreSQL — 22 passed. `alembic check` расхождений не находит.
- Обновление базы с 0.1 при существующих данных: 0001 с записями → 0002 → core.balance перевыпущен.
- E2E системы обновлений (`client/tools/e2e_update.sh`, живой сервер + клиент + CLI):
  `PUBLISH active=[core.balance@1, fortress.autumn_fair@1] decor=9 music_override=true`,
  `ROLLBACK active=[core.balance@1] decor=0`,
  `RESUME first=cancelled second_ok=true resumed_bytes=524288`,
  `CORRUPT last_error=hash_mismatch active_unchanged=true`, `KILL active=[] decor=0`,
  `RESTORE active=[core.balance@1, fortress.autumn_fair@2] decor=9`. В БД сервера записаны отчёты ok, hash_mismatch и kill_switch.
- Полный E2E UI: бои 1-1 и 1-2 в реальном времени, после перезапуска прогресс совпадает (`RESTART ... -> OK`).

## Ограничения
- Источников VIP (покупки, Battle Pass) пока нет: VIP выдаётся командой CLI.
- Текстуры из пакетов грузятся без VRAM-сжатия. Для крупных паков позже нужны KTX2/Basis или ETC2.
- APK на реальном устройстве по-прежнему не проверен.
- Ближний бой иногда сбивается в кучу в центре. Позже стоит добавить разведение по линиям и окружение цели.
