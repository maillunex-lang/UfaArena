# Выбор технологии Admin Studio (Android APK + браузер)

## 1. Исходные условия [Код][Док]

- Админка сегодня — веб-страница на том же FastAPI (`/admin`), уже есть WebView-обёртка `admin_app/`.
- Нужна браузерная версия (ПК для тяжёлой работы, телефон — для оперативной).
- Предпросмотр 3D уже сделан на `<model-viewer>` (веб). Игра имеет Web-экспорт Godot (`/play`, docs/ui/build.md).
- Команда фактически одна (владелец + ИИ-разработчик): поддержка двух кодовых баз — дорого.
- Сервер слабый: ничего не рендерить на сервере.

## 2. Варианты

**A. Kotlin + Jetpack Compose** — нативное Android-приложение.
**B. Flutter** — Dart, свой движок рендеринга, Android + Web.
**C. React + TypeScript + Capacitor** — SPA (Vite), в APK через Capacitor (нативная оболочка + плагины), та же сборка
в браузере.
**D1. Godot-приложение админки** — отдельный Godot-проект, переиспользующий `UI.gd` игры.
**D2. Только PWA** (без APK) — то же SPA, «установить на главный экран».

## 3. Сравнение (1 — плохо, 5 — отлично)

| Критерий | A Compose | B Flutter | C React+Capacitor | D1 Godot | D2 PWA |
|---|---|---|---|---|---|
| Качество Android APK | 5 | 4 | 4 | 3 | 2 (не APK) |
| Удобство мобильного управления (формы, клавиатура) | 5 | 4 | 4 | 2 | 4 |
| Сложный визуальный редактор (дерево, инспектор, холст) | 3 | 4 | 5 (богатая экосистема) | 3 | 5 |
| Изображения и GLB | 3 (SceneView/Filament) | 3 (плагины) | 5 (`model-viewer`, three.js — уже в проекте) | 5 (родной glTF) | 5 |
| Производительность холста | 5 | 5 | 4 (DOM/Canvas, достаточно для макетов) | 5 | 4 |
| Drag & Drop (тач) | 4 | 4 | 4 (dnd-kit/Sortable — уже в проекте) | 3 | 4 |
| Работа с файлами (загрузка ассетов) | 5 | 4 | 4 (Capacitor Filesystem / `<input>`) | 2 | 3 |
| Сетевая интеграция | 5 | 5 | 5 | 4 | 5 |
| Планшеты | 5 | 5 | 5 (адаптивная вёрстка) | 4 | 5 |
| Браузерная версия | 1 (нет) | 3 (Flutter Web тяжёлый) | 5 (та же сборка) | 3 (Web-экспорт ~30 МБ) | 5 |
| Скорость разработки | 2 | 3 | 5 | 2 | 5 |
| Поддержка и масштабирование | 4 | 4 | 5 | 2 | 4 |
| Сложность обслуживания (одна кодовая база) | 2 (+веб отдельно) | 4 | 5 | 2 | 5 |
| **Сумма** | 49 | 52 | **60** | 40 | 56 |

Важный особый случай D1: Godot отрисовывает **настоящий** интерфейс игры — это лучший способ сделать
**Game Runtime Preview**, но плохая основа для форм, таблиц, загрузок и длинных списков.

## 4. Рекомендация [Предложение]

**C. React + TypeScript + Vite + Capacitor** для Admin Studio, плюс **Godot для Runtime Preview** (тот же игровой
клиент в режиме предпросмотра: Web-экспорт во встроенном окне Studio и/или тестовый Android-клиент).

Обоснование:
1. Одна кодовая база для APK, планшета и браузера (требование «будущая браузерная админка»).
2. Уже используемые веб-инструменты (`model-viewer` для GLB, SortableJS для перетаскивания) переносятся напрямую.
3. Редактор интерфейса работает с **данными** (схема UI), а реальную картинку даёт Godot — поэтому сверхбыстрый
   нативный холст не критичен; DOM-рендер схемы (контейнеры ≈ flexbox/grid) близок к контейнерам Godot.
4. Capacitor даёт нативные функции, которых нет у WebView-обёртки: файловый выбор, безопасное хранилище токенов
   (Android Keystore через плагин), биометрия для подтверждения опасных операций, push (позже).
5. Текущая обёртка `admin_app/` остаётся до готовности Studio (ничего не ломаем).

Компромиссы:
- Холст Pro-режима на слабых телефонах медленнее нативного → ограничиваем: виртуализация дерева, рендер только
  видимого экрана, тяжёлые проверки на сервере.
- Capacitor-приложение — это WebView: «нативность» ниже Compose. Для админ-инструмента приемлемо.
- Нужна сборка Node/Gradle в CI или на машине разработчика (сейчас APK админки собирается без Gradle) — см.
  OPEN_QUESTIONS Q-T2.

## 5. Предлагаемый стек [Предложение]

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript (strict) | Типизированные контракты с API (генерация из OpenAPI FastAPI) |
| Сборка | Vite | Быстро, статические файлы раздаёт тот же FastAPI (`/studio`) |
| UI-кит | React + headless-компоненты (Radix) + CSS-переменные темы URALIA | Доступность, тёмная тема |
| Состояние | TanStack Query (сервер) + Zustand (редактор) | Кэш запросов, undo/redo в редакторе |
| Формы и схемы | JSON Schema → автогенерация форм (react-jsonschema-form или свой рендер) | Одна схема для формы и валидации |
| Перетаскивание | dnd-kit | Тач + клавиатура |
| Холст Pro | DOM-рендер схемы UI + overlay (выделение, направляющие); Konva — только для свободного позиционирования | Близость к контейнерам Godot |
| 3D | `@google/model-viewer` | Уже используется |
| Android | Capacitor 6 + плагины Filesystem, Preferences/SecureStorage, Biometric | Нативные возможности |
| Тесты | Vitest + Playwright | Playwright уже используется для админки |
