# План реализации [Предложение]

Принцип: каждый этап полезен сам по себе, ничего не ломает и не требует нового APK игры без необходимости.
Сложность: S — дни, M — 1–2 недели, L — 3–5 недель, XL — больше (оценки для одного разработчика с ИИ-помощником).

| Этап | Содержание | Зависит от | Сложность | Новый APK игры? |
|---|---|---|---|---|
| **0. Основа безопасности** | TLS (Caddy), учётки админов, роли, сессии, step-up, аварийный токен; расширение `admin_actions` | — | M | нет |
| **1. Configuration Registry (сервер)** | таблицы реестра, схемы, адаптеры: `ai.*` (Section), `ui.*` (layout), `heroes/campaign` (overrides); чтение `registry.active()` с кэшем | 0 | L | нет |
| **2. Жизненный цикл** | черновики, changeset, валидация, approval, publication, activation, rollback; идемпотентность; ZIP-патчи → changeset | 1 | L | нет |
| **3. Studio-фронтенд (браузер)** | React+TS: вход, реестр, формы по JSON Schema, diff, approval, история, патчи/задания ИИ, мониторинг (реальные данные) | 0–2 | L | нет |
| **4. Studio APK** | Capacitor-сборка, secure storage, биометрия для step-up, загрузка файлов, «Загрузки» | 3 | S–M | нет (APK админки) |
| **5. Экономика под управление** | вынос констант `data.py` (кошелёк, награды, здания, призыв, звёзды, квесты) и JSON-файлов в реестр без изменения значений; прогноз экономики в валидации | 1–2 | M | нет |
| **6. Медиатека** | ассеты, версии, связи, неиспользуемые, миниатюры, OGG/шрифты | 2 | M | нет (для новых форматов в клиенте — да) |
| **7. Окружения** | staging-теневой режим, канал `stable` для prod-сборки, перенос публикаций | 2 | M | **да** (канал в сборке) |
| **8. Клиент: ConfigClient + тема** | config-пакет, совместимость, LKG, отчёт Applied; тема в рантайме | 2, 7 | L | **да** |
| **9. UI-редактор Simple** | тема, тексты, иконки, видимость/порядок, пресеты; DOM-превью | 3, 8 | M | использует APK из этапа 8 |
| **10. UIRuntime + Pro** | каталог компонентов, UIRuntime в Godot, Pro-холст (дерево, инспектор, адаптивность), перенос экранов волнами | 8, 9 | XL | **да** (UIRuntime), далее волны — да |
| **11. Runtime Preview** | preview-токены, Godot Web в Studio, deep link в APK | 8 | M | **да** |
| **12. Сегменты и эксперименты** | правила сегментов, раскатка %, журнал экспозиций | 1 | M | нет (серверные) |
| **13. Локализация** | ключи строк в клиенте, конфиги `l10n.*` | 8 | L | **да** |

Рекомендуемый порядок: 0 → 1 → 2 → 3 → 5 → 4 → 6 → 7 → 8 → 9 → 11 → 10 → 12 → 13.
Предметы и экипировка — **вне Studio**: сначала нужна игровая система (проект + код), потом её конфиги попадут в реестр.

## Оценка по модулям

| Модуль | Сложность | Главный риск |
|---|---|---|
| Auth & RBAC + TLS | M | доступ к домену/сертификату |
| Configuration Registry + адаптеры | L | аккуратный перенос без изменения поведения игры |
| Validation | M | полнота бизнес-правил |
| Publishing/Versions | L | атомарность серверных и клиентских частей |
| Asset Management | M | лимиты памяти VPS при миниатюрах |
| Preview (Static/Interactive) | M | расхождение DOM-рендера с Godot |
| Runtime Preview | M | вес Web-экспорта на телефоне |
| Godot ConfigClient + тема | L | правки по всему UI-коду |
| UIRuntime + Pro-редактор | XL | объём переноса экранов |
| Studio фронтенд + APK | L | объём интерфейса |
| Мониторинг | S–M | — |
