# Итоговый отчёт фазы 01 — URALIA ADMIN STUDIO

Пометки: **[Код]** — найдено в репозитории, **[Док]** — из документации проекта, **[Предложение]** — решение этой фазы.

1. **Что обнаружено.** Godot 4.5.1, UI собирается кодом через `UI.gd`, только портрет, локализации нет [Код].
   Сервер — монолит FastAPI, 105 таблиц, 266 маршрутов, Redis только для лимитов [Код]. Админка — одна HTML-страница
   плюс WebView-APK [Код]. Конфигурации разбросаны по пяти местам: код, JSON-файлы, ~20 ключей `server_settings`,
   слой правок, контент-пакеты [Код]. Один VPS на 2 ГБ [Док]. Подробно — AUDIT_CURRENT_STATE.
2. **Что готово.**
   - Контент-доставка: подписанные неизменяемые манифесты, каналы, атомарное применение, откат, отчёт клиента [Код].
   - Редакторы героев, кампании, карт, раскладки меню, разделов ИИ, магазина [Код].
   - Слоты графики и 3D, ZIP-патчи с заданиями для ИИ [Код].
   - Аудит действий, идемпотентность, лимиты запросов [Код].
3. **Что требует расширения.**
   - Аудит: нужно «до/после» и привязка к пользователю.
   - Версионирование: сейчас разрозненное.
   - `content_installations`: добавить версии конфигов.
   - Раскладка UI: v1 → схема компонентов.
   - Мониторинг, аналитика, переключатели функций (без таргетинга) [Код + Предложение].
4. **Чего нет.**
   - Учётки админов, роли, сессии, TLS [Код].
   - Единый реестр конфигураций; DRAFT/APPROVAL; окружения staging/prod (APK слушают `dev`) [Код].
   - UI-рантайм по схеме, тема в рантайме, локализация [Код].
   - Предметы и экипировка, сегменты, эксперименты, медиатека с версиями и связями [Код].
5. **Технология APK.** React + TypeScript + Vite + Capacitor, одна кодовая база для APK и браузера. Godot — только для
   Runtime Preview (тот же игровой клиент) [Предложение]. Обоснование и сравнение — TECHNOLOGY_SELECTION.
6. **Общая архитектура.**
   - Модуль `app/studio` внутри существующего FastAPI. Новых постоянных процессов нет: используются существующие
     планировщик, хранилище по SHA-256 и подписанные манифесты.
   - Серверные конфиги активируются в реестре.
   - Клиентские конфиги уходят config-пакетом через существующие манифесты [Предложение].
   - Подробно — ADMIN_STUDIO_ARCHITECTURE, SYSTEM_COMPONENTS.
7. **FULL CONTROL.** 25 систем в четырёх категориях A–D с правилами «сервер / пакет / нужен APK» (GAME_CONTROL_MATRIX).
   Логику (категория D) администратор параметризует только из перечней, известных коду. Новые типы эффектов,
   компоненты и механики добавляются релизом [Предложение].
8. **Hybrid-редактор.**
   - Одна модель — UI Document (`uralia.ui/2`): компоненты из каталога, построенного на функциях `UI.gd`; свойства
     с токенами темы; привязки `bind` из реестра; слоты для блоков, ещё не переведённых на схему.
   - Simple — рычаги поверх документа. Pro — дерево, инспектор, холст, адаптивные правила.
   - Перенос экранов волнами, экран всегда можно вернуть к встроенному коду [Предложение] (UI_EDITOR_ARCHITECTURE).
9. **Preview.** Static (макет) и Interactive (макет с переходами и состояниями) работают в Studio. Game Runtime —
   настоящий клиент Godot (Web или APK) по preview-токену, только в памяти. Режимы честно подписаны [Предложение].
10. **Применение изменений.**
    - Цикл DRAFT → PREVIEW → VALIDATION → APPROVAL → PUBLISHED → ACTIVE.
    - Идемпотентная публикация, блокировка окружения.
    - Applied подтверждают клиенты через существующий `verify-install` [Код + Предложение].
11. **Откат.**
    - Активируется предыдущая неизменяемая публикация.
    - Клиентская часть откатывается через `activate` и манифест [Код], аварийно — через kill switch [Код].
    - Сущности, на которые уже ссылаются игроки, скрываются, а не удаляются [Предложение].
12. **Изменения в Godot.**
    - ConfigClient поверх `Content` и тема в рантайме (константы → переменные).
    - UIRuntime и каталог компонентов, перенос экранов.
    - Preview-режим, канал сборки (`stable`), расширенный отчёт Applied; локализация — по решению [Предложение].
13. **Изменения на сервере.**
    - TLS, учётки и роли, реестр с адаптерами существующих настроек.
    - Валидация, публикации, окружения, медиатека, `studio_jobs`.
    - Расширение `admin_actions` и `content_installations`.
    - Миграции только аддитивные, с `0017` [Предложение].
14. **Риски.**
    - Токен админки идёт по HTTP без TLS [Код].
    - Мало памяти на VPS [Док].
    - Перенос констант может незаметно изменить поведение игры (нужны тесты «до = после»).
    - Широкая правка темы в клиенте.
    - Объём Pro-редактора.
    - Расхождение DOM-превью с Godot (снимается Runtime Preview).
    - Смена канала у установленных APK.
    - Админ-одиночка утверждает сам себя (step-up).
15. **На согласование.** 18 вопросов с рекомендациями — OPEN_QUESTIONS_AND_DECISIONS. Ключевые: Q-T1 (технология),
    Q-S1 (TLS и домен), Q-E1/Q-E2 (окружения и канал), Q-P1/Q-P2 (когда переводить на APPROVAL и как обходиться с
    ZIP-патчами).
16. **Последовательность.** 0 безопасность → 1 реестр → 2 жизненный цикл → 3 Studio в браузере → 5 экономика →
    4 Studio APK → 6 медиатека → 7 окружения → 8 клиент: ConfigClient и тема → 9 Simple → 11 Runtime Preview →
    10 Pro и UIRuntime → 12 сегменты и эксперименты → 13 локализация (IMPLEMENTATION_ROADMAP).
17. **Сложность по модулям.** Безопасность — M; реестр и жизненный цикл — L + L; Studio-фронтенд — L; APK — S–M;
    экономика — M; медиатека — M; окружения — M; клиент — L; Simple — M; Pro и UIRuntime — XL; Runtime Preview — M;
    сегменты — M; локализация — L.

**Фаза 01 завершена.** Работа остановлена до подтверждения владельца. К фазе 02 и программированию Studio не перехожу.
