# Управление версиями [Предложение]

## 1. Сейчас [Код]

| Что | История | Откат |
|---|---|---|
| Разделы ИИ (`Section`) | 30 версий в `<key>_history` | к предыдущей |
| `ai_director` | 30 версий | к предыдущей |
| `game_overrides` (герои, кампания, карты) | 50 версий | к предыдущей |
| `ui_layout` | 30 версий, номер версии растёт и при откате | к предыдущей, сброс |
| Магазин | `catalog_changes` по полю | revert отдельного изменения |
| Контент-пакеты | неизменяемые манифесты (`content_manifest_versions`) | активация любой старой |
| ZIP-патчи | 30 записей со снимком затронутого | только последний |

Истории разрознены, сравнения версий (diff) в интерфейсе нет, защиты от одновременного редактирования нет
(последний сохранивший перезаписывает).

## 2. Единая модель

- **ConfigVersion** — неизменяема (только INSERT; UPDATE/DELETE запрещены на уровне репозитория и триггером БД
  [Предложение] `BEFORE UPDATE ON studio_config_versions … RAISE`), `sha256` от канонического JSON.
- **Publication** — набор версий, опубликованных вместе (changeset → publication), тоже неизменяема.
- **Activation** — журнал указателей окружения (`environment, config_id → version`), каждая смена — новая строка;
  «текущая» = последняя.
- История UI = история конфигов модуля `ui`; история ресурсов = `AssetVersion`; история публикаций = `Publication`.

## 3. Сравнение и просмотр

- Структурный diff JSON (по путям, как `patches.diff` [Код]) + представление по типу: для героя — таблица полей,
  для UI — подсветка узлов дерева и «до/после» в превью, для ассетов — изображения рядом.
- Сравнить можно любые две версии одного конфига или две публикации.

## 4. Восстановление, отмена, откат

| Действие | Смысл | Реализация |
|---|---|---|
| Восстановить версию N | сделать её содержимое новым черновиком | новый Draft с `base_version = текущая`, документ = N |
| Отменить публикацию | версия опубликована, но ещё не активна | Publication → `withdrawn` (версии остаются в истории) |
| Откат | активной сделать предыдущую версию | новая Activation на старую версию; статус ROLLED_BACK у отменённой |
| Откат changeset | откатить все конфиги, опубликованные вместе | одна транзакция активаций |

Откат **никогда** не удаляет данные игроков; если версия создавала сущности, на которые уже ссылаются игроки
(герой у игроков, пройденный этап), откат делает их скрытыми/отключёнными, а не удаляет (как в патчах v1 [Код]).

## 5. Ветки черновиков и конфликты

- Несколько черновиков одного конфига (`branch_name`), каждый с `base_version`.
- Оптимистическая блокировка: `ETag = sha256(черновика)`, запись с `If-Match`; не совпало → 409 с текущим состоянием.
- При публикации черновика, чья `base_version` ≠ активной: трёхсторонний merge по путям JSON (база / активная /
  черновик); непересекающиеся изменения сливаются автоматически, пересекающиеся — конфликт в UI.
- Мягкая блокировка «редактирует Имя» (присутствие в Redis, TTL 60 с) — предупреждение, не запрет.

## 6. Хранение

Версии маленькие (KB). Хранить все версии конфигов бессрочно; аудит — бессрочно; черновики без активности 90 дней —
архив; бинарные ассеты без ссылок — архив через 180 дней (удаление — вручную Super Admin).
