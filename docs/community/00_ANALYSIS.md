# 00. Анализ существующей системы

## Что уже есть (используем, не дублируем)
| Компонент | Файл | Что умеет | Ограничения для Living Community |
|---|---|---|---|
| Сценарии бесед ИИ | `server/app/social/ai/banter.py` | 18 жёстких сценариев на 2–3 роли (арена, призыв, тактика, флирт ИИ↔ИИ…), подбор ролей по стилю, подстановки (`{hero}`, `{food}`…), реплики в очереди с паузами 12–55 с; одиночные реплики (`ambient`); реакции эмодзи | Сценарии линейные (строго по очереди), почти все про игру; очередь `_queue` **в памяти процесса** — теряется при перезапуске; нет веток, вопросов, адресации по смыслу |
| Темп чата | `banter.flush`, `in_pause` | ≤ 1 сообщение ИИ в 10 с на канал; тишина 5–15 мин после обсуждения (в БД) | Хорошая база для BALANCED; сцена должна жить внутри этих рамок |
| Ответы игрокам | `social/ai/dialogue.py` | Намерения по ключевым словам (11), реплики по 6 стилям, анти-повтор окна 120 | Только игровые темы, нет off-topic |
| Речь | `app/ai/speech.py` | Манера персонажа (присказки, эмодзи, восклицания, маленькие буквы), эмоции от настроения, длина, контекст из памяти, языковая модель (необязательно, D-09a: локальная / бесплатные внешние) | Нет сленга/мата/юмора как отдельной оси; LLM используется только для ответов игрокам |
| Личность | `app/ai/personality.py` | 8 черт, амбиции, привычки, голос, настроение, эволюция от событий, версии | Нет интересов вне игры (кроме игровых `interests`) |
| Отношения | `app/ai/social.py`, `ai_relationships` | симпатия, доверие, соперничество, неприязнь, история 20 событий; группы (круги) | Нет «внутренних шуток», нет уровня «можно грубо шутить» |
| Память | `app/ai/memory.py`, `ai_memory` | виды (факт, разговор, обещание, отношения…), важность, архив, биография | Нет «незавершённых тем», нет краткосрочной памяти сцены |
| Каналы | `app/social/channels.py` | global, guild, region, event, alliance, group, dm, news; участие ИИ по видам; ИИ пишут только там, где есть читатели | Нет каналов 18+ |
| Director | `app/ai/director.py`, `ai_tasks`, `ai_events` | Задачи с ключами, приоритеты, бюджет такта, сон без игроков, лимит заходов | Нет сущности «сцена» |
| Фильтр чата | `social/chat.py` `clean()` | Маскирует запрещённые слова `***`, ссылки, телефоны | ИИ-сообщения сейчас пишутся напрямую в `ChatMessage`, **мимо `clean()`** (только `_say` и `flush`) |
| Возраст игрока | — | **Отсутствует** (нет даты рождения/подтверждения 18+) | Критично для взрослого юмора (см. D-C1) |

## Точки интеграции
1. **Director** — новый вид задач `scene_tick` (продвинуть активные сцены) и шаг планирования сцен вместо
   `chat_keepalive` (старый путь остаётся запасным).
2. **banter.flush / темп** — публикация реплик сцены проходит через тот же механизм пауз (10 с, тишина 5–15 мин).
3. **speech.compose / stylize** — финальная манера каждой реплики; LLM-адаптер `llm.py` — генерация (по флагу).
4. **social.relate / memory.add / personality.evolve** — последствия сцены.
5. **channels.ai_may_post / readers_online** — где можно говорить.
6. **chat.post / clean** — все ИИ-реплики должны проходить через фильтр (сейчас — нет; исправить в этапе 02).
7. **Админка «ИИ-жители»** — новый раздел «Живое сообщество» (настройки, просмотр активных сцен, журнал).

## Вывод
Делать надстройку **Scene Engine** над существующими модулями: сцена = новая персистентная сущность, всё остальное
(личность, отношения, память, каналы, темп, речь, LLM) — переиспользуется. Старые сценарии `banter.SCRIPTS` становятся
одним из источников «заготовок ходов», а не единственным механизмом.
