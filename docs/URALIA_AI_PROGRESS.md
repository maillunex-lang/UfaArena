## ФАЗА 2. БАЗОВОЕ ЯДРО (этапы 1, 3, 15, 17)

**MASTER SPEC CHECKPOINT (до):** перечитаны этапы 1, 3, 15, 17, разделы 5 (Director), 6 (БД), 8 (производительность);
зависимость — ИИ v1 (`server/app/social/ai`); конфликт найден и устранён: очереди ответов v1 жили в памяти процесса API
и были бы невидимы отдельному сервису и терялись при перезапуске → перенесены в БД (`ai_events`).

**Выполнено**
- Реестр популяции: 500 зарегистрированных ИИ по умолчанию, рост порциями (`spawn_per_run`), ИИ не удаляются; v1
  больше не «отключает» лишних ИИ — активность регулируется сессиями (этапы 1, 3).
- Активность отдельно от регистрации: цель активных = `active_min + 3 × реальный онлайн` × режим × нагрузка, в пределах
  `active_min…active_max` (30…150) (этап 3).
- Расписания: 7 групповых профилей (жаворонки, днём, вечерние, совы, по выходным, изредка, усердные), личный часовой
  пояс, длительность сессии, дни отдыха, пиковые часы, ручной запуск персонажа (этап 15).
- AI Director: отдельный процесс (`python -m app.ai`, сервис `ai-director`), один на всю популяцию; события игры →
  задачи; планирование; приоритеты; исполнение через те же игровые функции; аренда задач, повторы с отсрочкой,
  восстановление после сбоя; адаптивный бюджет (сжимается при медленных тактах или медленной БД); сердцебиение и
  метрики; сжатие очереди в историю (этап 17, раздел 5).
- Режимы: выключен / **тестовый (по умолчанию)** / обычный / повышенная активность / низкая нагрузка; при остановке или
  сбое Director сервер автоматически продолжает работу на ИИ v1 (этап 20).
- Админ-API: состояние и настройки Director с проверкой и откатом, очередь задач и повтор, расписания, популяция,
  ручной запуск (часть этапа 18).

**Требования, оставшиеся по этим этапам:** событийные триггеры кроме сообщений (поздравления, вступления и т. п. —
фазы 4–5), реакция активности на события мира (этап 15 — фаза 5), автоматические режимы при перегрузке (этап 19 — фаза 7),
графический интерфейс Control Center (этап 18 — фаза 6), горизонтальное масштабирование нескольких Director
(подготовлено: `SKIP LOCKED` + аренда; проверка — фаза 7).

**MASTER SPEC CHECKPOINT (после):** реализация сверена с этапами 1, 3, 15, 17 и разделом 5 (у задачи есть ID, тип,
ИИ, приоритет, время создания, условие запуска, статус, лимит повторов, результат, ошибка; идемпотентность по ключу,
действие и завершение в одной транзакции). Противоречий с утверждёнными решениями нет.

### 0.6. Базовые замеры (локально, SQLite, 1 процесс)
500 ИИ создаются за 7,2 с; такт текущего движка (12 действий) — **0,59–0,94 с**, пик выделений памяти 3 МБ; база с 500 ИИ —
4,7 МБ. Пропускная способность текущего такта (каждые 15 с) ≈ 2 900 действий/ч — достаточно для 500 ИИ × 40 действий/день
(≈ 830/ч). PostgreSQL на VPS будет медленнее на сетевых задержках; замер повторить там на этапе 3.

### 0.7. Аудит VPS — нужны данные с сервера
Из среды разработки доступа к VPS нет. Команды для заказчика (результат прислать):
```bash
nproc; free -h; swapon --show; df -h /; uptime
docker compose -f /opt/uralia/docker-compose.yml ps
docker stats --no-stream
docker compose -f /opt/uralia/docker-compose.yml exec db psql -U uralia -c "select pg_size_pretty(pg_database_size('uralia'));" -c "select count(*) from pg_stat_activity;" -c "select count(*) filter (where is_ai) ai, count(*) filter (where not is_ai) real from player_profiles;"
ss -s | head -3
```
