# Монетизация URALIA (гибридная F2P)

**Текущий режим: ТЕСТОВЫЙ.** Реальные платежи заблокированы на сервере. Все товары покупаются тестовыми покупками, которые проходят полный цикл: заказ → подтверждение → выдача → журнал.

## Принципы
- Игру можно пройти бесплатно. Рекламы нет.
- Любой платный бонус доступен и бесплатно: герои — в призыве, осколки — в лавке и призыве, ресурсы — в AFK и кампании, VIP-опыт — за активность и достижения.
- PvP пока не реализован. VIP-бонусы (AFK +до 10%, скорость боя) относятся только к PvE и удобству.
- Мифических героев за деньги не продают: только призыв и события.
- Цены и награды хранятся только на сервере: `server/app/game/content/monetization.json` → таблица `shop_products`.

## Безопасность
- Права игрока определяет только сервер. Клиент ничего не выдаёт сам.
- Все изменяющие запросы идут с ключом идемпотентности. При подтверждении заказ блокируется на уровне строки БД. ID транзакции провайдера уникален. Тест: 8 параллельных подтверждений одного заказа выдают товар ровно один раз.
- Отрицательных балансов нет: списание проверяется до записи. Журнал транзакций неизменяемый, сверка баланса с журналом покрыта тестами.
- Админка выключена, пока не задан `URALIA_ADMIN_TOKEN` (не короче 24 символов). Все действия пишутся в `admin_actions`.

## Режимы платежей
`GET /api/v1/shop/status` → `{"mode": "test"}`.

Включить коммерческий режим можно только при выполнении всех условий:
1. На сервере задано `URALIA_PAYMENTS_COMMERCIAL_ALLOWED=1`. Без этого сервер работает как тестовый, даже если в БД записано иное.
2. Есть реализованный и настроенный реальный провайдер. **Сейчас таких нет.**
3. Владелец ввёл фразу подтверждения: `docker compose exec api python -m app.content.admin payments-mode commercial --confirm "<фраза>"` или через `/admin`.
4. Переключение пишется в журнал. Откат: `payments-mode test`.

## Что осталось для реальных платежей (нужен доступ владельца)
1. **RuStore:** аккаунт разработчика, приложение в консоли, ключи RuStore Pay API (`URALIA_RUSTORE_APP_ID`, `URALIA_RUSTORE_KEY_ID`, `URALIA_RUSTORE_PRIVATE_KEY`). Нужно реализовать `RuStoreProvider.verify_purchase` и разбор уведомлений, на клиенте — плагин RuStore Billing для Godot.
2. **Google Play:** консоль, сервисный аккаунт с доступом к Android Publisher API (`URALIA_GOOGLE_PACKAGE_NAME`, `URALIA_GOOGLE_SERVICE_ACCOUNT_JSON`). Проверка через `purchases.products.get` и `purchases.subscriptionsv2.get`, возвраты через RTDN (Pub/Sub). На клиенте — плагин Google Play Billing для Godot (нужна gradle-сборка APK).
3. Создать товары в консолях с теми же SKU, что в каталоге.
4. Юридическое: оферта, политика возвратов, налоги и чеки (54-ФЗ для продаж в РФ), возрастная маркировка.
5. Release-подпись APK и HTTPS на сервере.

До этого все кнопки покупки в игре проводят только тестовые покупки.
