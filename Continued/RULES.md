# Правила работы (обязательные)

## Git
- Работать и пушить только в ветку **`ccr-39bc6428-16s1r4`** (`git push -u origin ccr-39bc6428-16s1r4`).
- Ветка `apk` — только файл `uralia-latest.apk` (и README), с разрешения заказчика.
- Pull request не создавать, пока заказчик не попросит.
- Окончание каждого сообщения коммита (две строки, как есть):
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01Mco3UPxqUd85PY6n3JAM1h
  ```
  (если работает другой ИИ — свою подпись по его правилам; идентификаторы моделей в код и документы не писать).

## Перед коммитом
- Сервер: `cd server && .venv/bin/python -m pytest -q` — коммитить только при 0 failed (проверять итоговую строку!).
- Миграции: проверка на PostgreSQL (`alembic upgrade head`, `alembic check`, откат на одну назад и обратно).
- Клиент: `godot --headless --path client res://tools/Check.tscn` → `broken=0`.
- Изменения админки — посмотреть в браузере (Playwright), без ошибок JS.

## Продукт (из мастер-ТЗ ИИ и решений заказчика)
- Не создавать новую игру вместо существующей; не переписывать работающие механики без необходимости.
- Не удалять/не повреждать аккаунты; не терять прогресс игроков; миграции только аддитивные, с откатом.
- Не менять игровые правила без согласования; не использовать платные внешние ИИ-API (бесплатные — только по выбору
  заказчика в админке, D-09a); один процесс Director на всю популяцию; не перегружать VPS.
- ИИ всегда помечены как ИИ, не выдают себя за людей; без фальшивых покупок/VIP; приватность и отказ игрока соблюдать.
- **APK не собирать до фазы 8**, если заказчик явно не попросит; подпись приложения не менять.
- Секретов сервера в APK нет; ключи — только в `.env` на сервере или в админке (не возвращаются, не логируются).
- Реальные платежи выключены (тест-режим).
- Протокол этапа: MASTER SPEC CHECKPOINT до и после, обновить `docs/URALIA_AI_*.md`, отчёт из 10 пунктов (§11),
  инструкция по обновлению сервера.

## Обновление сервера (давать заказчику после каждого патча)
```bash
cd /opt/uralia
docker compose exec db pg_dump -U uralia uralia > backup_$(date +%Y%m%d_%H%M).sql   # если есть миграция
git pull
docker compose up -d --build
docker compose logs --tail=40 api | grep -i upgrade      # если есть миграция
```
